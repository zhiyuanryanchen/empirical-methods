## 1. 讲座概述

### 背景

基于现有1.5小时邀请讲座（`one-stop-research-vscode-llm/slides.qmd`，已在RUC经济学院和CUFE国际经济与贸易学院讲授两场）和4天完整课程大纲（`AI-For-Research/syllabus.qmd`，24小时），为南京大学商学院设计2次×2小时=4小时的讲座系列。

### 设计选择

经过讨论，确定以下关键选择：

| 决策 | 选择 | 理由 |
|------|------|------|
| 内容策略 | **方案A：工具链深化** | 4小时无法承载LLM文本分析模块；深度优于广度 |
| 两讲切分 | **切法2：工具认知→完整实操** | Session 1集中讲完AI助手全景，Session 2专注MCP和写作 |
| 实操比例 | **纯讲授+Demo** | 保留现有讲座风格，Q&A放在结尾 |
| 听众 | 混合（研究生+教师） | 需兼顾操作落地性和概念深度 |

### 两讲递进逻辑

```
Session 1 (2hr)：把台子搭稳          Session 2 (2hr)：让水流起来
─────────────────────────           ─────────────────────────
VS Code 工作台 ──────┐               MCP 工具桥接 ──────┐
Git/GitHub 安全网 ───┤ 基础设施       Stata/Matlab Demo ──┤ 专业工具
AI 助手全景 ────────┘               LaTeX/Slides 写作 ──┘
     ↓                                    ↓
"知道有什么、怎么选"                  "让工具互相说话、产出论文"
     ↓                                    ↓
本周小任务                           七步工作流 + 最小行动
```

## 2. 设计原则

（来自教学记忆，应用于本次讲座设计）

- **Slides作为脚手架**：不为塞满内容而写slides，给口头发挥留足空间（讲师风格：26个偏离/50分钟）
- **每Session设置2个主动检查点**（~30分钟和~60分钟）：停顿2分钟，直接面对观众问"到目前为止有没有问题？"——回应当前教学中"连续demo无停顿"的待改善模式
- **每Session有结构化的2-3分钟收尾仪式**：不讲新内容、不重复slides文字，而是用不同角度说"今天如果只记住三件事..."
- **关键slides附带speaker notes（口头钩子）**：一个故事、一个类比或一个演示动作
- **"先秀伤口再给药"**：保留并强化个人失败故事（AI删文件夹、30页错误证明）作为信任建立的锚点
- **讲前确认听众背景**：根据现场调整案例选择

### 3.2 各段内容详情

#### 开场 + 问题诊断（12 min）

- AI如何改变研究时间分配（选题40%→执行10%→审阅50%）
- 传统碎片化研究的痛点：数据在Excel，清洗在Stata，图在Python，正文在Word，AI在浏览器
- "一站式科研"的核心主张：把研究动作组织成可重复、可检查、可交接的流水线
- 两讲路线图预览
- **口头钩子**：手机类比——"为什么信任手机但不能盲信AI？"—留到Session 2合适位置或用开场建立悬念

#### VS Code 工作台（13 min）

- "基座"比喻——"一切都是编程"重定义（写do-file是编程，写LaTeX是编程，写Markdown也是编程）
- 五大区域在研究中的用途（Explorer/Editor/Terminal/Chat/Source Control）
- 现场导览VS Code界面
- `:::{.concept-box}` "为什么经济学研究者需要一个编程基座？"

#### 🔴 检查点1（5 min）

"到目前为止有没有什么问题？VS Code界面大家能看到吗？"

#### Git/GitHub 安全网（25 min）

- 为什么AI时代更需要版本控制——AI一次改多个文件，Git让你随时知道改了哪里
- Git基本命令完整演练：`init → add → commit → diff → log`
- "血泪教训"故事两个：
  - AI删文件夹+"轻声说Sorry"
  - 30页错误证明读了两周发现是错的
- GitHub远程备份 + `gh repo create` 一键创建
- 给AI的安全要求：`git status` → 修改 → `git diff` → 验证 → commit
- 重点区分Git本身（开源免费）与GitHub（代码托管平台，2018年被微软收购）

#### 🔴 检查点2（5 min）

"Git这部分有没有疑问？特别是`git diff`和commit的关系。"

#### 推荐插件 + 项目结构（15 min）

- 六大插件（Python/Jupyter/Stata Enhanced/MATLAB/LaTeX Workshop/GitLens）
- `code --install-extension` 一键安装命令
- 标准化项目结构：`data/raw/ scripts/ notebooks/ output/ paper/ prompts/ audit-log.md`
- 演示研究题目："数字化转型与企业生产率"DID分析

#### AI 助手全景（25 min）

- 工具对比表——Copilot（行内补全）、Copilot Chat（侧边栏问答）、Claude Code（终端agent）、Codex/Trae（IDE agent）
- "船长与航行员"比喻——Copilot角色定位：船长决定航向，航行员处理重复操作，船长永远不能把手离开舵轮
- 三种AI交互模式深度讲解：
  - **Ask**：只聊不改——问概念、查API
  - **Plan**：先想清楚再输出框架——复杂任务、多文件
  - **Agent**：托管执行——边界清晰、已验证的流程
- Plan模式最被低估：高阶模型做Plan → 低价模型执行 → 效果好、成本低、可校验
- Agent模式最快但最容易上瘾：开始前确保有一次干净的commit

#### 操作演示（10 min）

给Agent一个检查研究流水线的任务。观察点：是否先读项目、是否控制修改范围、是否真的运行验证命令。

#### 🟢 收尾仪式（5 min）

"今天如果只记住三件事——基座（VS Code统一工作台）、安全网（Git让你回得去）、谁做什么（Ask/Plan/Agent梯度使用）。"

#### 本周小任务（2 min）

把一个正在做的项目放进VS Code，建立标准化目录结构，运行`git init -b main`完成第一次commit。

### 4.2 各段内容详情

#### Session 1 回顾（5 min）

"上次我们搭了台子——VS Code统一工作台、Git安全网、AI助手谁做什么。这次我们让工具互相说话，从数据一路跑到论文。"

#### CLI 与 MCP（15 min）

- CLI是命令行入口——研究者或脚本直接运行命令（`stata -b do`、`matlab -batch`），强调可重复、可记录
- MCP是AI调用外部工具的协议——自然语言描述任务→AI通过MCP交给Stata/Matlab/R→结果带回上下文
- "MCP的本质"类比：导师说"结果不太显著，调一调控制变量"→科研助理回去跑一个下午→MCP让AI成为那个"回去跑回归的助理"
- CLI vs MCP场景对照表：固定流程→CLI；探索问题+多工具衔接→MCP

#### MCP 架构图 + 配置实操（10 min）

- MCP架构图展示（AI→MCP Server→Stata/Matlab/R/文件系统）
- 两种服务器类型：`"type": "http"`（远程服务）和 `"command"+"args"`（本地进程stdio）
- 现场打开 `.vscode/mcp.json`，展示配置结构
- 工作区级 vs 用户级的作用域区分
- 安全警告：避免硬编码API Key，使用环境变量；仅添加可信来源服务器

#### 🔴 检查点1（5 min）

"CLI和MCP的区别清楚吗？mcp.json的配置大家能看到吗？"

#### Stata MCP 现场演示（20 min）

- 用自然语言让AI通过MCP调用Stata：描述统计 → DID回归 → 事件研究图
- 展示完整闭环："自然语言→MCP→Stata执行→结果返回→AI解释"
- MCP不可用时的fallback方案：保留可直接运行的CLI脚本

#### Matlab MCP 现场演示（15 min）

- Matlab在数值优化、结构估计和仿真中的价值
- 现场演示：用自然语言让AI通过MCP调用Matlab做功效分析
- 展示输出表格如何进入AI上下文并辅助解释

#### 🔴 检查点2（5 min）

"Stata和Matlab的MCP演示——有问题吗？有哪些工具你们希望也能接进来？"

#### 从结果到写作（25 min）

**Notebook：快速备忘录（5 min）**

- 适合当天完成的产物：数据诊断、一张图、一个表、一段解释
- `jupyter nbconvert` 导出HTML/slides

**LaTeX Workshop：正式论文（5 min）**

- VS Code中左侧编辑`.tex`、右侧预览PDF
- 保存自动编译，错误直接定位到行
- BibTeX/Biber管理参考文献

**Beamer：学术汇报Slides（5 min）**

- AI辅助生成Beamer frame：从论文摘要→5张frame（标题页、研究动机、识别策略、主要结果表、结论）
- `\begin{frame}{...}...\end{frame}` 格式
- 与论文共享公式、图表和参考文献

**现场demo（5 min）**

演示：用一个prompt生成中文和英文两版"结果解释"段落，展示AI从研究备忘录直接写出论文小节。

**逐句检查清单（5 min）**

AI写作的正确姿势：先给数据和结果，再让AI写解释——不要先被漂亮段落说服。检查：识别假设是否准确？变量定义是否正确？标准误层级是否说明？结论边界是否明确？

#### 七步工作流 + 结束语（15 min）

- 一站式科研七步完整串讲：建项目→建仓库→写脚本→做备忘录→接工具→正式写作→留记录
- **"效率之外"**：如果枯燥的重复正在消磨科研热情，把机械工作交给AI，把原创思考留给自己——学术共同体才有接力人
- **"眼界决定解决方案"**：知道那个东西存在（GPU可以加速、分块可以降内存）本身就有巨大价值——眼界决定了你能提出什么问题
- **"论文如孩子"**：研究者仍然负责问题识别、责任承担、伦理考量
- **"脱缰的野马"警告**：思想的草原本是茂密生长，AI一阵狂奔后一片狼藉——深度思考必须亲自做

#### 🟢 收尾仪式（3 min）

"两天的讲座如果只记住一件事——把研究从'你在操作软件'变成'软件为你工作'，而你的工作是判断、是审阅、是决定什么是好的研究。"

#### 行动号召（2 min）

"回去后只做一件事——把你的一个项目文件夹放进VS Code，完成第一次Git commit。然后选一个最低风险的任务交给Copilot。"
